# academic-search 会话、可靠性与治理讨论稿

状态：讨论中，尚未实现。
定位：定义搜索与 RAG 任务如何保存状态、抵抗失败、控制资源使用，并保障用户资料与学术输出可追溯。
关联：检索任务见 [`03-literature-search-and-discovery-discussion.md`](03-literature-search-and-discovery-discussion.md)；RAG 文献索引见 [`05-rag-research-workspace-discussion.md`](05-rag-research-workspace-discussion.md)。

---

## 1. 会话与数据边界

产品采用短生命周期的搜索会话，而不是沿用旧系统的单机工作区文件状态。一次搜索会话关联原始输入、方向选择、查询、provider 调用、候选文献、排序结果和用户选择。

RAG 引入后，需要增加研究集合、文献、文档版本、片段、索引版本和问答记录等实体。每项数据必须明确归属用户与研究集合，检索和 Agent 调用时始终带上这一边界。

数据持久化采用 PostgreSQL；Redis 用于短期缓存、分布式锁、限流和异步任务协调。不能以本地 JSON 文件或单进程内存状态作为多用户服务的真实数据源。

## 2. 异步任务与可观测性

以下工作必须以异步任务执行：多源检索、题录补全、全文获取与解析、文档切块、向量嵌入、RAG 回答中的长耗时处理。

不能用 FastAPI `BackgroundTasks` 或进程内字典作为生产任务的唯一执行和状态方案：进程重启、多个 API 实例或 Worker 扩容都会导致任务丢失或状态不一致。短生命周期的搜索、题录与全文获取使用 Redis 搜索会话状态和 arq 队列协调；在正文校验成功前，它们不创建候选或论文的 PostgreSQL 长期记录。`ingestion_runs` 与 `research_runs` 则是可恢复的持久化任务真相，独立 Worker 必须将其状态、错误、重试和最终结果回写 PostgreSQL。

全文获取的短期状态需记录任务类型、搜索会话、开始和结束时间、当前阶段、重试次数、错误类别与最终结果；成功后将最终来源类型、HTTP/文件校验摘要和内容 SHA-256 写入 `documents`。不得记录用户密钥、Cookie 或上游响应正文。

文献候选至少保留 `triage -> citation -> fulltext -> reader` 四阶段状态。RAG 入库需要额外记录 `parse -> chunk -> embed -> index` 阶段，以及 `queued`、`running`、`completed`、`failed` 等运行状态；阶段失败不能被压缩为一个笼统的“任务失败”。当前 Worker 在每次阶段完成时回写 PostgreSQL，Milvus 成功而最终状态提交失败时会执行按运行 ID 的补偿删除。

前端通过 SSE 获得状态变化；刷新页面后应能从服务端恢复真实状态，而不是丢失任务进度。

RAG 运行还要持久化结构化 trace：查询、候选池大小、Hybrid/RRF 召回结果、父块合并、精排、证据路由、改写方式、子问题和最终引用片段。成功响应必须在保存回答与 trace 后才能发送完成事件；错误响应不得伪装为成功完成。客户端取消时，Worker 应取消仍在运行的模型调用，并释放请求级资源。

## 3. Provider 可靠性与成本控制

学术数据源和模型服务都存在限速、配额与临时不可用的问题。系统需要：

- provider 级别的跨进程限速、并发控制和配额预留。
- 多源冗余，单个 provider 失败时不阻塞全部工作流。
- 对可重试错误实施退避重试，对不可恢复错误保留清晰原因。
- 缓存可复用的检索、题录和解析结果，避免重复外部调用。

MVP 不接支付、不设付费墙。资源治理仍然必需：深度引用说明、RAG 入库和 RAG 问答均应有单用户频率限制、每日使用上限和全局预算熔断。自动任务只能处理用户主动加入研究集合的文献，不能自动向量化所有检索结果。

对 Agent 工作流还需设置：最大查询改写次数为一次、最大子问题数、最大并行检索数、每节点超时和总 token 预算。HyDE/Step-back 等改写文本只在当次任务中保存为检索 trace，不能进入可引用知识库。

## 4. 隐私、版权与学术诚信

### 4.1 用户资料隔离

用户上传的文献、研究问题、问答记录和研究集合可能包含敏感信息。所有读取、向量检索和缓存键都必须按用户与研究集合隔离；禁止将一个集合的片段召回给另一个集合。

### 4.2 全文与版权

系统仅访问开放获取、官方允许获取或用户有权上传的文件。首版自动获取只处理 Provider 明确给出的开放获取直链 PDF；文献原文链接优先指向官方来源或开放获取来源；系统不绕过付费墙，也不提供盗版镜像。拥有 DOI、落地页或猜测性 PDF 地址都不构成可入 RAG 的正文。

### 4.3 研究结论的可审计性

推荐理由、引用说明和 RAG 回答必须能回溯到输入文献与具体证据。模型配置、提示词版本、检索结果和引用片段需要在服务端保留足以复现和排查的记录。

不能让系统生成无证据的论文结论或将用户不拥有的内容暴露给他人。

## 5. 运行指标

| 维度 | 需要监控的指标 |
|---|---|
| 任务可靠性 | 成功率、失败类型、重试次数、阶段耗时 |
| 数据源 | provider 错误率、限速命中率、响应时间、缓存命中率 |
| 成本 | 每次搜索、每篇入库、每次问答的模型与外部 API 消耗 |
| RAG 质量 | 检索命中率、引用可定位率、回答受证据支撑率 |
| 检索链路 | Hybrid 降级率、父块合并次数、精排失败率、改写与澄清路由比例 |
| 安全 | 跨用户访问拒绝数、上传失败原因、异常请求频率 |
