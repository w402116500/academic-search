# academic-search 文献结果与引用讨论稿

状态：讨论中；格式中立题录补全、引用格式化与研究集合准入服务已实现，真实结果页和准入 HTTP 编排尚未实现。
定位：定义文献结果如何呈现、如何证明推荐理由、如何让用户正确复制和使用引用。
关联：候选产生与排序见 [`03-literature-search-and-discovery-discussion.md`](03-literature-search-and-discovery-discussion.md)；RAG 研究问答见 [`05-rag-research-workspace-discussion.md`](05-rag-research-workspace-discussion.md)。

---

## 1. 要解决的问题

用户拿到论文标题并不等于能使用它。结果页需要帮助用户在短时间内判断“为什么值得读”“原文在哪里”“可如何引用”，同时避免系统替用户做无依据的学术判断。

每条结果的交付目标是四件套：论文入口、推荐理由、正式引用格式、可追溯的引用说明。

## 2. 文献结果表与详情检查器

桌面端结果主视图是可排序、可筛选的高密度文献表，不用高度不一的大卡片。表格使用户能横向比较多篇论文的题录、全文与 RAG 准入状态；点击行或“查看详情”后，在右侧检查器查看不适合放入表格的长文本。移动端以紧凑可展开行与底部抽屉承载同一信息。

结果行默认信息包括：

- 标题、作者、年份、出版来源和文献类型。
- 相关性分数、来源、引用量、开放获取性等可解释信号。
- DOI 题录、全文与 RAG 准入状态。
- 原文、DOI 或官方落地页链接，以及复制引用与查看详情入口。

详情检查器展示摘要、完整推荐理由、题录详情、可访问全文入口、证据片段和引用说明。摘要与推荐理由的正文行宽应受限，避免在宽屏中横跨整个画布。

结果行与详情检查器必须区分三个事实：

- 有题录：可生成或复制正式引用，但不代表系统拥有正文。
- 有全文链接：来源提供了可能的入口，但尚未代表链接可访问、文件合法或已保存。
- 可研究：题录核验通过，且正文已经实际获取、校验、保存并完成索引；只有这一状态可进入 RAG 问答。

## 3. 推荐理由与证据要求

推荐理由不是模型的主观好评，而是“该论文与当前研究方向的哪一部分匹配”的解释。

每条理由至少应指向一个可核验依据：标题、摘要、元数据字段，或已合法获取的全文片段。理由必须明确区分以下两类内容：

| 内容 | 允许的表述 |
|---|---|
| 论文直接陈述或实验结果 | 引用原文片段，并给出来源与定位 |
| 系统归纳出的相关性判断 | 标注为系统判断，并说明使用了哪些证据 |

无法得到证据的内容不能作为确定事实展示。全文不可用时，理由只能基于摘要和元数据，并在界面中标记证据范围。

推荐理由和引用说明均采用“生成 -> 证据核验”两步：先形成结构化的候选主张，再检查每项主张是否被对应片段直接支持。核验失败的主张必须移除或降级为待用户核对的提示，不能仅因文本通顺而展示给用户。

## 4. 正式引用格式

MVP 结果行默认提供 GB/T 7714-2015 编号制的快捷复制动作。论文详情页提供引用格式选择与预览，可导出 GB/T 7714-2015、APA 7、MLA 9、Chicago author-date 和 BibTeX。后端始终从同一份已核验的格式中立题录生成这些结果，前端不得为任一格式手工拼接文本。

系统需要：

1. 通过 DOI 内容协商取得 CSL-JSON，并提取作者、日期、标题、来源、卷期页码、文章号、出版者、DOI 与 URL。
2. 只补齐候选中缺失的字段；与已有字段不一致时保留候选值并记录冲突值及来源。
3. 校验作者、年份、标题、来源、卷期页码、DOI/URL 等关键字段完整性。
4. 对无法完全补齐、存在跨源冲突或 DOI 服务暂时失败的题录，分别显示 `partial`、`conflict`、`unresolved` 状态；这些状态不能生成看似完整的标准引用。
5. 使用 CSL 引擎渲染文本样式，使用专用 BibTeX 序列化器导出 BibTeX，不能为不同格式维护手工拼接模板。
6. 提供一键复制，并在复制成功后给出明确反馈。

复制正式引用不要求系统已经取得全文，但加入研究集合要求更严格：必须同时具备 `ready` 题录、非空 DOI 和一份已验证的可处理全文。题录完整但全文不可得时，结果行仍应允许打开官方入口或复制引用，但“加入研究集合”动作应显示不可用原因，并提供“上传有权处理的 PDF”入口。

## 5. 引用说明功能

引用说明是产品的差异化能力。用户点选一篇论文后，系统生成的不是整段代写文本，而是一份“如何引用这项研究”的说明。

推荐输出结构：

```text
可支持的观点：该研究能够支撑什么限定范围内的陈述。
证据：论文中的相关原文片段。
建议表述：带引用标注的、可供用户修改的表述模板。
适用限制：该结论适用的对象、数据或条件。
来源定位：论文、章节/页码、原文链接与 GB/T 题录。
```

强制要求：

- 建议表述必须携带引用标注，复制时不能静默丢失。
- 明确区分作者的结论与系统的归纳，不扩大论文的因果或适用范围。
- 证据不足、全文无法可靠解析或论文结论本身存在条件限制时，优先提示用户核验。
- 界面文案应说明这是“学习如何引用他人研究”，不是替用户写论文。
- 系统的查询改写、HyDE 假设文本或模型内部推理不能作为引用内容的证据来源。

当前共识是将它设计为免费但受服务端限流的单篇能力；是否进入 MVP 仍需要最终确认。

## 6. 用户动作与反馈

| 用户动作 | 系统反馈 |
|---|---|
| 打开原文 | 跳转官方或开放获取来源，并标明访问类型 |
| 复制 GB/T 题录 | 显示复制成功，复制内容保持标准格式 |
| 加入研究集合 | 先核验 DOI 题录并获取、校验全文；成功后显示“正在解析与建立索引” |
| 全文不可获取 | 保留查看与复制题录；说明无法进入 RAG 的原因，并在适用时提供 PDF 上传入口 |
| 展开理由 | 显示依据与证据范围，而不只扩展模型文本 |
| 生成引用说明 | 显示生成状态、来源证据与可编辑模板 |
| 文献题录缺失 | 明确缺失字段和已尝试的数据源 |

## 7. 成功标准

- 用户无需离开结果表与详情检查器即可判断论文是否值得进一步研究。
- 每个推荐理由都有与之匹配的证据边界。
- GB/T 题录可直接复制使用，错误和缺失信息不会被隐瞒。
- 不会把“有 DOI”或“有全文链接”误展示为“已可用于 RAG 研究”。
- 引用说明能帮助用户正确归因，而不越界为论文代写。

## 8. 待决定的问题

1. 引用说明是否确定进入 MVP，还是在核心检索质量稳定后上线？
2. 默认结果行显示哪些质量信号，哪些放到详情检查器？
3. 首版已确定同时提供 APA 7、MLA 9、Chicago author-date 与 BibTeX；后续是否需要增加其他 CSL 样式？
4. 全文不可获取时，引用说明是否只允许输出摘要级别的观点，还是完全不开放？
