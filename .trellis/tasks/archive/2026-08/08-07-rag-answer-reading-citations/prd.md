# RAG 回答阅读与引用交互

## Goal

将研究会话中的回答从难以扫读的纯文本和全量证据列表，升级为可阅读、可核查、可回到文献详情的学术回答界面。用户应能在不离开当前回答的前提下检查正文引用，并明确区分快速问答与深度研究的可信边界。

## Background

- `ResearchChatView.vue` 当前将助手回答以纯文本段落展示，并将一次运行的全部证据直接展示为来源。
- API 已为每条 `ResearchEvidence` 提供 `is_cited`、`display_index`、`paper_id`、`citation_excerpt` 和 `locator_snapshot`。后端已将用户可见正文引用转换为 `[1]` 等展示索引。
- 当前研究范围已在页面加载；范围文献含 `paper_id`，可以与证据关联后在 `ResearchScopeDrawer` 内展示详情。
- 完整回答应有至少一条可回链证据；`awaiting_clarification` 且没有实际引用的终态代表本轮无法给出受支持的事实性回答。

## Requirements

### R1. 安全且可扫读的回答正文

- 助手回答支持标题、段落、强调、列表、引用块和表格等受限 Markdown。
- 原始 HTML、脚本和嵌入媒体不得渲染或执行；模型输出不能成为 Vue 模板。
- 正文中的 `[n]` 必须渲染为受控、可访问的前端引用按钮，而不是模型生成的 HTML 或外链。

### R2. 以实际引用为默认来源

- 已完成且有引用的回答，下方默认收起显示“引用来源”。列表只包含 `is_cited=true` 的证据，并使用 `display_index` 排序。
- 快速问答不得展示未实际引用的候选证据。
- 深度研究可在独立、默认收起的“候选证据”区域展示未引用证据；该区域不能混入“引用来源”。
- 引用卡片展示论文标题、作者、定位信息和已保存的原文摘录。

### R3. 正文引用检查与文献详情

- 点击正文 `[n]` 时，页面保持在当前答案：展开“引用来源”、滚动到对应卡片、视觉高亮并将焦点交给该卡片。
- 点击来源卡片的论文标题时，打开当前研究范围的文献详情抽屉并选中对应论文；不得路由跳转。
- 引用找不到研究范围文献时，保留当前界面并给出明确的局部提示，不伪造详情。

### R4. 快速问答与深度研究的透明度

- Fast RAG 只展示运行当前状态和紧凑完成审计摘要；其核验标签只能表述“引用已检查”。
- Strict Research 可额外展示实际收到的阶段轨迹与候选证据；其核验标签可表述“引用与主张已核验”。
- 阶段轨迹只能来自 SSE 实际事件；不得模拟逐字输出或虚构阶段。刷新后的持久恢复以 `ResearchRun` 审计摘要为准。

### R5. 证据不足状态

- 终态运行若没有实际引用且处于澄清/证据不足边界，显示独立的“证据不足”状态，不展示无来源的事实性结论或空来源列表。
- 状态可说明当前集合不足、提示用户补充范围或问题，并提供切换到深度研究的明确入口；它不是系统错误。

### R6. 可访问、响应式和既有工作台风格

- 保持现有蓝白、双栏、安静高密度的研究工作台风格，不引入深色渐变、玻璃拟态、固定第三栏或营销页构图。
- 引用按钮、来源展开状态、当前高亮证据和详情抽屉均有可访问名称、键盘可达性和合适的焦点行为。
- 窄屏下正文、来源列表、抽屉和长论文标题不得溢出或遮挡。

## Out Of Scope

- 不改变 Fast RAG 或 Strict Research 的后端检索、生成、核验、持久化与 API 契约。
- 不实现逐字流式回答、对话导出、全文阅读器、PDF 内嵌阅读器或新的独立文献页面。
- 不在快速问答中暴露候选证据，不将来源列表长期固定展开，也不增加右侧第三信息栏。

## Acceptance Criteria

- [ ] 完成回答中的 Markdown 在桌面与窄屏下可读，原始 HTML、脚本和嵌入媒体均不会执行或显示为可执行内容。
- [ ] 正文 `[n]` 是可访问的引用检查控件；点击后会展开、滚动、高亮并聚焦对应 `display_index` 的引用卡片，且 URL 与当前对话不变。
- [ ] “引用来源”默认收起，且只显示 `is_cited=true` 的证据；审计标签的数量与实际引用数量一致。
- [ ] 深度研究可见实际 SSE 阶段轨迹和默认收起的候选证据；快速问答不显示两者，且两种模式的核验文案正确区分。
- [ ] 点击引用或候选证据的论文标题可在研究范围详情抽屉中选中匹配 `paper_id` 的文献；无匹配时给出局部提示。
- [ ] 证据不足终态不显示无依据结论或空的“引用来源”，并可引导用户澄清或改用深度研究。
- [ ] 新增聚焦单元测试和 Playwright 覆盖，现有研究会话治理、研究范围详情和移动布局行为不回归。

## Open Questions

无。产品、范围、交互、安全边界和验收标准均已确认。
