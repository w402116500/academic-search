# 候选审核、研究集合与 RAG 研究范围

## Goal

让用户在一次连续、可理解的研究流程中完成“检索候选 -> 自动核验题录与全文可得性
-> 选择文献 -> 建立研究集合 -> 基于可读全文进行 RAG 问答”。用户只负责判断文献
是否值得保留，不必理解题录补全、公开全文探测、下载、解析和向量入库这些后台步骤。

产品必须明确区分“我选中的文献”与“当前能作为 RAG 证据的文献”，同时不因题录或
PDF 暂不可用而丢弃用户已经选中的书目。

## Confirmed Facts

- 当前候选的标题、摘要、来源原始记录和审核状态只保存在 Redis 搜索会话中；数据库保留
  检索运行的汇总状态、统计和 Redis 键，不保存候选快照。
- 当前 Redis 搜索会话默认 TTL 为 7200 秒。候选快照不存在时，候选分页接口把运行标为
  过期，前端显示“候选会话不可用”。
- 当前题录预补全存在固定上限，导致同一检索中部分候选有正式引用、部分未尝试补全；现有
  正式引用输出只接受已核验的 `ready` 题录。
- 当前筛选页已经采用“候选列表 + 右侧详情检查器”的工作台布局，包含多选和批量操作；
  该布局是后续 UI 改造的基线，不另建独立核验页。
- 当前全文、解析、嵌入与向量索引属于后续入库链路。RAG 只应使用实际完成入库的全文证据。

## Product Decisions

- 每次检索完成后，系统对所有进入候选审核池的候选自动执行一次题录核验与公开全文
  可获得性探测。相关性已明确排除、不会进入用户筛选的原始记录不消耗外部核验配额。
  候选审核不再要求用户执行“准备核验”或单篇/批量核验。
- 题录核验只决定能否生成正式引用，不决定候选能否被选择或加入研究集合。
- 题录无法使用时，界面只显示“该题录暂不可用”；不展示上游错误、字段缺失、冲突或限流
  等内部原因，不提供用户主动重试。服务端必须保留可追溯的结构化失败日志。
- 正式引用仍只能由已核验的 `ready` 题录生成，不能从候选展示字段拼接伪造引用。
- 筛选阶段只探测公开 PDF 是否可获得，不下载 PDF、不解析 PDF、不建立向量索引。
- 用户可将任意候选加入研究集合，包括题录暂不可用或没有可自动获取 PDF 的候选。
- 研究集合保存用户选中的全部书目；RAG 研究范围只包含 PDF 已获取、解析、切块和索引
  均完成的文献。
- “加入研究集合”是启动 RAG 构建的唯一用户确认动作。系统立即下载已探测到的公开 PDF 并
  执行入库，不增加“开始构建”或同类显式步骤。下载失败后系统最多自动再试一次；仍不可用
  时保留该集合文献，并显示“需上传 PDF”。
- 用户上传 PDF 后自动进入同一入库链路。只要 RAG 研究范围中至少有一篇文献完成入库，
  即可开始问答。
- 删除集合文献时，同步清理其 PDF、解析文本、向量和入库记录。PDF 与候选 DOI 或标题
  明确冲突时拒绝进入 RAG；PDF 仅缺少可提取标识但文件有效时允许入库。

## Functional Requirements

### R1. 检索完成后的自动核验

- 系统必须覆盖本次候选审核池的全部候选，不得再以固定预补全上限造成未尝试的候选。
- 系统必须限制 DOI/题录上游调用的并发、重复请求与自动重试，避免无界请求和限流放大。
- 自动核验完成后，每个候选应有可供 UI 消费的稳定题录状态和 PDF 可获得性状态。
- 用户不需要、也不能通过界面重新触发单篇或批量题录核验。

### R2. 候选审核工作台

- 保留工作区侧栏、三阶段导轨、紧凑行式候选列表和右侧详情检查器。
- 候选行必须同时呈现相关性、题录状态和 PDF 状态。推荐用户可见文案为：`题录已核验`、
  `该题录暂不可用`、`可自动获取 PDF`、`需上传 PDF`。
- 右侧详情以“文献详情”为标题，固定顺序展示正式引用、PDF 可用性、相关性依据；不展示
  底层失败原因。
- 页面不再显示“待准备核验”“准备单篇核验”或“准备单篇核验”对应的中间操作。
- 多选后的唯一主操作是“加入研究集合（X）”。加入操作不能因题录或 PDF 状态阻塞。
- 加入研究集合成功后，已探测到公开 PDF 的文献立即进入下载和入库；用户在集合页查看状态，
  不需要再次确认构建。

### R3. 研究集合与 RAG 研究范围

- 证据研究阶段必须同时可见“研究集合”总数与“RAG 研究范围”可研究数量，不得把两者
  混为同一计数或同一状态。
- 研究集合视图列出全部已选文献及其当前入库状态：已进入 RAG、正在入库、需上传 PDF。
- `需上传 PDF` 的文献保留在集合中，并提供上传入口；上传成功后自动进入入库，不要求
  用户执行额外构建步骤。
- RAG 问答只查询已完成入库的文献；集合中缺 PDF 的书目不得作为回答证据。

### R4. 可观测性与失败呈现

- 题录和 PDF 的内部失败原因写入后端结构化日志，包含运行、候选、阶段与可安全记录的
  错误码，不向用户暴露 Provider 原始响应或凭据。
- UI 面向用户使用稳定的结果状态，不把系统重试、外部限流、解析异常等技术控制暴露成
  用户动作。

## Acceptance Criteria

- [ ] 一次检索完成后，候选审核池中的全部候选都获得一次题录核验结果和一次公开 PDF 可获得性结果；
  不再存在“因预补全上限而从未尝试”的候选。
- [ ] 同一候选筛选页中，题录/PDF 状态不会阻止用户选择并加入研究集合；不可用题录不产生
  正式引用文本。
- [ ] 筛选页没有用户可点击的题录核验、重试或“准备核验”步骤，右侧详情不泄漏技术原因。
- [ ] 研究集合完整保留已选书目，并在任意时刻明确展示其与 RAG 研究范围的数量差异。
- [ ] 点击“加入研究集合”后，已探测到公开 PDF 的文献立即下载并入库；首次失败后自动重试
  一次，仍失败后改为“需上传 PDF”但不删除集合书目。
- [ ] 成功上传或自动下载的 PDF 完成解析、切块和索引后自动进入 RAG 研究范围；至少一篇
  可研究文献存在时，问答可用且只引用该范围内的证据。
- [ ] 删除集合文献后，其相关对象存储、解析、向量和入库记录不再属于该集合的研究范围。
- [ ] 自动核验与入库链路具有覆盖正常、题录不可用、PDF 不可得、下载重试、上传成功和
  DOI/标题明确冲突的测试。

## Out Of Scope

- 工作区永久删除、RAG 回答阅读/引用交互和既有研究范围详情任务的独立交付；它们保持由
  各自活跃 Trellis 任务负责。
- 放宽正式引用必须基于已核验题录的可信边界。
- 在筛选阶段下载全文或提前写入向量库。
- 向用户暴露第三方 Provider 错误、重试按钮、账号/网络配置或任何凭据。
- 更换认证、文献 Provider、代理配置或外部模型 Provider。
- 持久化完整候选快照、延长 Redis 会话 TTL，或让已完成检索跨 Redis 过期/服务重启恢复。

## Deferred Risk

- 现有候选快照只保存于 Redis，服务重启、Redis 数据丢失或 TTL 到期后，已完成运行的
  候选列表不可恢复。该问题已确认不在本轮范围内，后续作为独立的数据保留策略讨论。
