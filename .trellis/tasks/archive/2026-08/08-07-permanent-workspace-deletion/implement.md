# 工作区永久删除实施计划

1. 修复 SQLAlchemy 删除顺序：删除工作区私有 `ResearchEvidence`，再删除
   `ResearchRun`，最后删除工作区根记录，保留普通路径的 `RESTRICT` 外键。
2. 将 `deleting` 工作区纳入所有者列表 DTO；常规读取与写入仍拒绝该状态。
3. 在服务与 API 边界记录可溯源的清理失败上下文，对前端统一映射为删除未完成提示。
4. 在侧栏渲染不可导航的删除中工作区和“继续删除”操作；在研究入口提供同一恢复入口。
5. 更新研究范围入口到聊天头部，保证窄屏可达。
6. 运行删除服务/API/live PostgreSQL、研究聊天与删除浏览器测试，以及相关静态检查。

## 回退点

- 若显式删除顺序仍无法满足数据库约束，停止在数据库事务边界排查关联所有权；不得把外键改为全局 `CASCADE`。
- 若恢复入口的 DTO 影响普通工作区列表，保留 `status` 的 canonical 字段并在前端按状态分流，不复制列表接口。
